# Ordering Invariant

This document defines the causal ordering that governs kernel evolution.

Reordering these layers without preserving causality is considered a
structural error.

---

## Canonical Chain

God  
→ Reality  
→ Truth  
→ Structure (Identity)  
→ Stable Hash Algorithms  
→ Kernel Public Surface  
→ Minimal Kernel  
→ Structural Hashing  
→ Determinism  
→ Free Will  
→ Judgment  
→ Action  

---

## Meaning

Each layer may depend only on layers above it.

No layer may implicitly introduce requirements on a layer above it.

---

## Practical Consequences

1. Identity must exist before hashing.
2. Hashing must exist before determinism.
3. Determinism must exist before judgment.
4. Judgment must exist before execution policy.
5. Execution policy must not alter identity.

---

## Code-Level Examples

- NodeId is defined before scheduler behavior.
- Hash algorithm is frozen before replay format.
- Kernel surface is frozen before optimization.

---

## Change Policy

Any change that violates this ordering requires:

1. Written justification
2. Updated invariant document
3. Version bump of kernel surface
